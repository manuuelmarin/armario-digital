# Registro del cambio: asistencia local opcional

Fecha: 31 de octubre de 2026. Base: `main` tras PR #8 (`0712f29c132947e2a4dcd655642e3fe9e1b315f3`). Aplicación 0.3.0, esquema 9, perfil estructurado 1, instrucciones `wardrobe-1`.

## Petición y decisiones

Implementar visión local con Qwen3-VL 4B Q4 y asociación textual independiente usando descripciones revisadas. Mantener la app privada, Python y funcionamiento manual. Sustituir la duplicación de «identificación/función» por siete grupos útiles y editables. Permitir sorpresa coherente, prendas fijadas, chaqueta, pantalón corto/largo, preferencias y sustitución de una pieza.

Se eligió Qwen3 4B Instruct 2507 Q4 para texto, ejecución secuencial en Ollama y descarga de memoria al finalizar. No se ejecuta un modelo en cada visita ni se añade un framework de ML. La preselección y las restricciones verificables pertenecen a Python; la evaluación semántica de compatibilidad pertenece al modelo. Los resultados numéricos son estimaciones ordinales, sin porcentajes de certeza.

## Implementación y trazabilidad

| Capa | Cambio |
|---|---|
| Protocolo | `ai_client.py`: endpoint loopback fijo, dos etiquetas, respuesta acotada, JSON estricto, huella de modelo antes/después, sin proxy/redirecciones/pull |
| Descripciones | `profiles.py`: narrativa, siete grupos, aprobación manual, revisión incremental y huella de fuente |
| Recomendación | `recommendations.py`: restricciones, estructuras completas, preselección acotada, evaluación textual y revalidación |
| Ejecución | `ai_jobs.py`, `run.py`: cola persistente, un trabajador, transacciones cortas, pausa/cancelación/reintento y recuperación de interrupciones |
| Interfaz | `assistant.py`, seis plantillas y `ai.js`: configuración, lotes, revisión, generación y resultados; formularios sin dependencia de JavaScript |
| Persistencia | Migración 009: ajustes, descripciones, tareas y procedencia de outfits; copia previa de la instalación existente |
| Guías | Uso local, arquitectura, datos, recuperación, seguridad, decisiones, pruebas e historial actualizados |

Cada tarea guarda su solicitud normalizada, estado, modelo, digest, versión de instrucciones y resultado validado; no se persiste el payload de fotografía. Las descripciones aprobadas conservan su procedencia y las correcciones son explícitas. Un outfit guardado conserva la procedencia de generación; editarlo manualmente retira las valoraciones del modelo.

## Auditoría de integridad y seguridad

- Sin descarga automática de pesos, servicios remotos ni claves de API. Las llamadas se producen solo por tareas solicitadas o pendientes previamente solicitadas.
- Una inferencia no bloquea las escrituras del inventario. Cancelar descarta resultados y no promete detener Ollama instantáneamente.
- Cambios de fuente, revisiones, archivo, borrado y traslados invalidan resultados antes de guardarlos. Las correcciones no se sobrescriben automáticamente.
- IDs, capas, filtros y perfiles se verifican en el servidor antes y después del modelo y al guardar. Se rechazan referencias inventadas, duplicados, resultados incompletos y propuestas mal valoradas.
- Las copias incluyen SQLite y las mismas imágenes verificadas; no incluyen pesos. La migración parte de una base poblada del esquema 8 y conserva fotos y relaciones.
- Los textos del modelo se escapan en HTML. No se ejecutan órdenes, scripts ni herramientas suministradas por un modelo.

## Verificación

Verificación local: Linux, Python 3.12.14 y Chromium 153. **94 pruebas aprobadas**, incluidas seis de navegador; Ruff, formato Python y formato de plantillas aprobados. Las capturas de resultados se inspeccionaron a 1.440 y 390 px, con imágenes cargadas y sin desbordamientos horizontales. El Chromium utilizado para QA procede de `@sparticuz/chromium` 153 instalado temporalmente fuera del proyecto; no se añade como dependencia de la app. CI utiliza la instalación estándar de Playwright.

Comandos reproducibles:

```bash
python -m ruff check .
python -m ruff format --check .
python -m djlint armario/templates --check
RUN_BROWSER_TESTS=1 python -m pytest -q
```

En la ejecución local se indicó además `BROWSER_EXECUTABLE` al binario temporal de QA. Sin navegador, la suite normal registra 88 aprobadas y seis omitidas. Las pruebas de IA usan datos ficticios, un servicio HTTP loopback de prueba y respuestas de modelos simuladas. Se distingue la prueba del contrato de una inferencia real. El flujo verifica también descripciones aprobadas, fotos y procedencia de outfits tras crear y restaurar una copia, y migración desde esquema 8 con relaciones de outfit, maleta, colección, etiqueta y tablero.

Pendiente de validación en el dispositivo del equipo objetivo: instalación interactiva de Ollama/Windows, descarga de pesos, consumo y latencia en un equipo objetivo de 32 GB y calidad de combinación con prendas reales. No se han descargado modelos ni creado un inventario personal para fingir esa validación.

## Límites aceptados

Una foto principal por análisis; una prenda por capa y hasta un accesorio; preselección aproximada con límites de contexto; sin entrenamiento/fine-tuning. El tipo y largo requieren revisión humana. La ocasión y estilo orientan el juicio, no son garantías. La documentación de uso describe los límites de la espera, de la cancelación y de la restauración de trabajos pendientes.
